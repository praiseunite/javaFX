Part 1 — Debugging Drills

A huge part of being a developer is reading code and figuring out why it doesn't work. The code snippets below have subtle bugs. Can you spot them?

Drill 1: The Forgetful Collection

Set<String> names = new HashSet<>();
names.add("Alice");
names.add("Bob");
names.add("alice");

System.out.println("We have " + names.size() + " unique names.");
// Output says: We have 3 unique names. 
// Wait, isn't Alice a duplicate? Why did the Set keep it?
💡 See the Bug & Fix

The Bug: Sets are case-sensitive. "Alice" and "alice" have different hash codes and are not equals() to each other in Java.

The Fix: Convert everything to lowercase (or uppercase) before adding it to the Set.

names.add(name.toLowerCase());

Drill 2: The Generics Crash

public static void addFruits(List<? extends Fruit> basket) {
    basket.add(new Apple()); 
    // ERROR: compiler refuses to compile this line!
}
💡 See the Bug & Fix

The Bug: You cannot add() to a list declared with ? extends. PECS (Producer Extends, Consumer Super). extends is for reading (producing) data. The compiler doesn't know what specific type of Fruit list was passed in (it might be a List<Banana>!), so it prevents you from adding an Apple.

The Fix: If you want to consume (add) items, use super.

public static void addFruits(List<? super Apple> basket) {
    basket.add(new Apple()); 
}

Drill 3: The Leaky File

public void writeLog(String msg) throws IOException {
    FileWriter writer = new FileWriter("app.log");
    writer.write(msg);
    // the end of the method
}
💡 See the Bug & Fix

The Bug: The FileWriter is never closed! This causes a resource leak. Worse, the data might be stuck in a buffer and never actually written to the disk.

The Fix: Use a try-with-resources block so Java closes it automatically.

public void writeLog(String msg) throws IOException {
    try (FileWriter writer = new FileWriter("app.log")) {
        writer.write(msg);
    }
}

Drill 4: The Frozen App

Object key = new Object();

public void doWork() {
    synchronized(key) {
        System.out.println("Doing work...");
        try {
            Thread.sleep(5000); // 5 second pause
        } catch (InterruptedException e) {}
    }
}
💡 See the Bug & Fix

The Bug: Thread.sleep() does not release the lock! While this thread sleeps for 5 seconds, every other thread that needs the key lock is completely blocked. This kills performance.

The Fix: Never sleep while holding a lock. If you need a thread to wait and give up the lock, use key.wait() instead of Thread.sleep().

Part 2 — The Mega-Quiz (Sessions 1–5)

Test your knowledge. Take your time. Discuss with your partner if you disagree on an answer!

Multiple choice
1. Which collection would you use to store a line of people waiting for a bus?
B. A Queue is FIFO (First-In-First-Out), exactly like a real-life line (queue).
Multiple choice
2. In a HashMap, what is required of the Keys?
C. Keys must be unique, and HashMap relies on hashCode() and equals() to find the right "bucket".
Multiple choice
3. Which Collection allows NO duplicates and does NOT guarantee insertion order?
C. HashSet has no duplicates and no order. (LinkedHashSet keeps insertion order, TreeSet sorts them).
Multiple choice
4. What is the main benefit of Java Generics (e.g., List<String>)?
A. Generics catch type errors at compile time before you run the code.
True / False
5. Because of "Type Erasure", a List<String> and a List<Integer> look exactly the same to the JVM at runtime.
True. Generics are a compile-time feature. The JVM just sees a raw List of Objects.
Multiple choice
6. If you want a method to ACCEPT a List of Numbers OR ANY SUBCLASS of Number (like Integer, Double), what syntax do you use?
B. ? extends Number is an Upper Bounded Wildcard. It accepts Number and anything below it.
Multiple choice
7. Which class is best for reading a text file (.txt) line-by-line?
A. Readers/Writers handle characters (text). Input/OutputStreams handle raw bytes. BufferedReader provides the handy readLine() method.
Multiple choice
8. What is the primary purpose of the Serializable interface?
D. Serialization is the process of turning objects into bytes.
Multiple choice
9. If you want to prevent a specific field (like a password) from being saved during Serialization, what keyword do you use?
B. The transient keyword tells the JVM to ignore this field when serializing the object.
True / False
10. With "try-with-resources", you MUST explicitly write a finally block to call .close() on your file streams.
False. That's the whole point of try-with-resources! It automatically closes AutoCloseable resources for you.
Multiple choice
11. What is the preferred way to create a Thread in Java?
C. Separating the "Job" (Runnable) from the "Worker" (Thread) is preferred.
Multiple choice
12. What happens if you call myThread.run() instead of myThread.start()?
B. start() tells the OS to branch into a new thread. run() is just a normal method call.
Multiple choice
13. Which method do you call if you want the Main Thread to pause and wait for Thread A to finish completely?
A. join() means "wait here until this thread terminates".
Multiple choice
14. What defines a Daemon Thread?
C. Daemon threads (like the garbage collector) automatically die when the main program finishes.
Multiple choice
15. What is a "Race Condition"?
C. It causes unpredictable data corruption.
Multiple choice
16. How do you prevent a Race Condition in Java?
D. synchronized ensures only one thread can access the code block at a time.
Multiple choice
17. A Deadlock occurs when...
A. It's a standoff where neither thread will yield.
Multiple choice
18. Why is an ExecutorService (Thread Pool) better than making a new Thread every time?
C. Thread Pools are much more efficient for system resources.
Multiple choice
19. If you need a thread-safe List, which class should you use?
B. CopyOnWriteArrayList is from java.util.concurrent and is thread-safe.
Multiple choice
20. What is the correct way to make a thread stop waiting and resume work?
B. notify() and notifyAll() are the standard ways to wake up threads from wait().
